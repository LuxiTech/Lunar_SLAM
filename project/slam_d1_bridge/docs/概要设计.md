# SLAM 到 D1 命令桥概要设计

## 1. 文档目的

本文档说明 `slam_d1_bridge` 第一期的系统边界、网络拓扑、ROS 2 接口、命令转换、
安全处理及后续扩展方向，作为开发、联调和验收的共同依据。

第一期重点实现 SLAM/导航速度命令到 D1 上层控制命令的转换与限幅。SLAM 位姿已经
接入并缓存，但暂不参与运动控制闭环。

## 3. 系统边界

### 3.1 第一期职责

`slam_d1_bridge` 负责：

- 订阅 SLAM/导航发布的速度命令；
- 将 `geometry_msgs/msg/Twist` 转换为 `ddt_msgs/msg/UserCommand`；
- 对前进、后退和转向命令进行限幅；
- 强制清除单机双轮足不支持的横移命令；
- 拒绝包含 NaN 或无穷值的速度命令；
- 以固定频率向 D1 发布最新有效命令；
- 输入命令超时后持续发布零速度；
- 订阅、缓存并基础校验 SLAM 位姿，为后续闭环功能预留数据。

### 3.2 第一期不负责

- 路径规划、避障和目标点管理；
- 根据 SLAM 位姿计算速度命令；
- 判断机器人是否到达目标；
- 把 SLAM 位姿转换成 D1 机身姿态命令；
- 重新发布 `/slam/pose`；
- 提供 SLAM 位姿的 HTTP 或大模型工具接口；
- 自动设置 `teleop_command/use_sdk`；
- 自动执行 `transform_up -> loco` 或趴下流程；
- 机器人机身俯仰、横滚或高度控制；
- 管理 `http_ros_gateway` 与本节点之间的控制权仲裁。

`slam_d1_bridge` 与 `http_ros_gateway` 不同时运行，因为两者都会发布 D1 的
`command/user_command`，并发运行会造成命令互相覆盖。

## 4. 术语与接口语义

### 4.1 SLAM 位姿

SLAM 位姿使用 `geometry_msgs/msg/PoseWithCovarianceStamped`，表示 `map` 坐标系下
机器人 `base_link` 的位置和朝向估计。它用于后续导航、大模型路径规划、到达判定和
运动闭环。

### 4.2 D1 机身姿态命令

`ddt_msgs/msg/UserCommand.pose` 是发送给 D1 的机身姿态控制命令，不是机器人的
地图定位信息。当前已知有用部分主要是姿态四元数所表达的机身角度。

SLAM 位姿和 D1 机身姿态命令虽然都使用 `Pose` 数据结构，但业务含义不同，禁止直接
映射。特别是 SLAM 的地图航向角不能写入 D1 `UserCommand.pose.orientation`；D1
转向必须通过 `UserCommand.twist.angular.z` 完成。

第一期不控制 D1 机身角度，每条命令均发送中性单位四元数：

```yaml
pose:
    position: {x: 0.0, y: 0.0, z: 0.0}
    orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}
```

## 5. 部署拓扑

系统包含三台 NX 设备：

```text
SLAM NX
  192.168.123.xx/24
  ROS_DOMAIN_ID=42
        │
        │ 有线交换机
        ▼
自有 NX（运行 slam_d1_bridge）
  有线：192.168.123.xx/24
  ROS_DOMAIN_ID=42
        │
        │ 有线交换机
        ▼
D1 内置 NX
  eth0：192.168.123.49/24
  wlan0：禁用
  ROS_DOMAIN_ID=42
```

三台设备第一阶段统一使用：

```bash
export ROS_DOMAIN_ID=42
export ROS_LOCALHOST_ONLY=0
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
```

所有 D1 控制参与者使用 Fast DDS 接口白名单，只允许回环接口和本机
`192.168.123.xx/24` 有线地址。控制机可以保留 Wi-Fi 上网，但 D1 发现和控制数据不会
进入 Wi-Fi、VPN 或虚拟接口；D1 自身的 `wlan0` 由 systemd/rfkill 禁用。

只有在 SLAM 无法使用 Domain 42、需要严格网络隔离，或者双网卡 DDS 经过实测仍不能
稳定工作时，才考虑引入 `domain_bridge` 或 DDS Router。

## 6. ROS 2 接口

### 6.1 输入话题

| 话题 | 消息类型 | 用途 |
| --- | --- | --- |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | SLAM/导航速度命令 |
| `/slam/pose` | `geometry_msgs/msg/PoseWithCovarianceStamped` | SLAM 地图定位 |

`/cmd_vel` 和 `/slam/pose` 为全局话题。节点虽然运行在 D1 namespace 下，但 launch
文件会把这两个输入显式 remap 到全局名称。

### 6.2 输出话题

| 话题 | 消息类型 | 用途 |
| --- | --- | --- |
| `/d15041873/command/user_command` | `ddt_msgs/msg/UserCommand` | D1 上层组合控制命令 |

代码使用相对输出名称 `command/user_command`，通过节点 namespace 解析为具体机器人
话题，避免在 C++ 中硬编码机器人序列号。

### 6.3 QoS

- `/cmd_vel`：Keep Last 1、Reliable、Volatile；
- `/slam/pose`：Keep Last 1、Reliable、Volatile；
- `command/user_command`：Keep Last 10、Reliable、Volatile。

D1 现场记录中的 `UserCommand` 订阅端为 Reliable、Volatile。SLAM 发布端联调时还需用
`ros2 topic info -v` 核对实际 QoS；若 SLAM pose 使用 Best Effort，桥的订阅 QoS需要
相应调整。

## 7. 命令转换设计

### 7.1 支持的运动自由度

当前 D1 为单机双轮足形态，不支持横移。第一期采用非完整约束运动模型：

- 支持前进和后退；
- 支持原地转向；
- 支持前进或后退过程中的弧线运动；
- 不支持左右横移。

### 7.2 字段映射

| SLAM `Twist` 输入 | D1 `UserCommand` 输出 | 处理方式 |
| --- | --- | --- |
| `linear.x` | `twist.linear.x` | 按 `max_linear_x` 对称限幅 |
| `linear.y` | `twist.linear.y` | 强制置零，超过容差时节流告警 |
| `linear.z` | `twist.linear.z` | SLAM 输入强制置零；高度控制器单独产生受限的升降速率 |
| `angular.x` | `twist.angular.x` | 强制置零 |
| `angular.y` | `twist.angular.y` | 强制置零 |
| `angular.z` | `twist.angular.z` | 按 `max_angular_z` 对称限幅 |

所有 Twist 分量在接收时都必须是有限数。任意字段为 NaN 或无穷值时，整条输入无效，
桥进入零速度输出。

`fsm_mode` 默认使用 `loco`，使桥运行期间持续维持已由外部启动流程建立的双轮平衡
状态。桥本身不执行站立或趴下转换。高度滑块给出 `0..9` 的单体双足档位，
上限对应旧 `0..30` 范围的 30% 位置；
网页将其显示为 `0..100%`。桥以 `1 档/s` 跟踪目标，再按 `0.03`
缩放为 `twist.linear.z`；厂家 LQR 按时间积分。

## 8. 发布与超时

输入接收与 D1 输出频率相互解耦：

```text
/cmd_vel 回调：随上游频率缓存最新有效命令
定时器：固定周期发布最新有效命令或零速度
```

默认发布周期为 50 ms，即 20 Hz。20 Hz 是 D1 SDK Demo 与已验证
`http_ros_gateway` 共同使用的基线，不代表 D1 的最高支持频率。发布周期保留为参数，
后续可通过实机联调评估更高频率。

D1 会保持最后一条运动命令，因此不能只在收到 `/cmd_vel` 时发布。若最后一条有效命令
超过默认 300 ms 未更新，定时器持续发布零速度，直到收到新的有效命令。

节点启动后，在收到第一条有效 `/cmd_vel` 前只发布零速度。节点正常析构时尝试再发布
一条零速度，但软件退出行为不能替代 D1 自身保护、物理急停或人工监护。

## 9. SLAM 位姿处理

第一期收到 `/slam/pose` 后：

- 缓存最新一条完整消息；
- 记录本机单调时钟接收时间；
- 检查 position 和 orientation 是否为有限值；
- 检查四元数范数是否明显无效；
- 对异常数据输出节流告警。

第一期不使用 SLAM pose 控制机器人，也不因 pose 缺失或异常停止 `/cmd_vel`。原因是
SLAM 定位质量、跟踪丢失状态和大模型闭环方式尚未确定，当前不能把“pose 超时”直接
等同于“机器人必须停止”。

后续可在接口明确后扩展：

- SLAM 跟踪状态和定位质量；
- pose 超时安全联锁；
- 大模型只读 HTTP/工具接口；
- 目标点、路径和到达判定；
- 基于定位反馈的航向或路径跟踪闭环。

## 10. 参数

| 参数 | 默认值 | 说明 |
| --- | ---: | --- |
| `input_topic` | `cmd_vel` | remap 前的速度输入名称 |
| `slam_pose_topic` | `slam/pose` | remap 前的 SLAM 位姿输入名称 |
| `output_topic` | `command/user_command` | D1 相对输出话题 |
| `publish_period_ms` | `50` | 输出周期，默认 20 Hz |
| `command_timeout_ms` | `300` | 速度命令有效期 |
| `max_linear_x` | `0.5` | 前进/后退绝对限值，单位 m/s |
| `max_angular_z` | `0.5` | 转向角速度绝对限值，单位 rad/s |
| `lateral_velocity_tolerance` | `0.001` | 横移输入告警容差，单位 m/s |
| `fsm_mode` | `loco` | 桥运行期间维持双轮平衡状态 |
| `height_fsm_mode` | `loco` | 双足 LQR 在原模式下处理 `linear.z` 高度速率 |

所有周期和限幅参数在节点创建 ROS 实体前完成合法性检查。周期必须大于零，限幅与横移
容差必须为有限非负数，话题名不得为空。

## 11. D1 操作边界

运动前需要由外部流程完成：

1. 确认机器人、场地、遥控器和物理急停安全；
2. 确认 D1 命令订阅端存在；
3. 设置 `teleop_command/use_sdk=true`；
4. 按已验证流程执行 `transform_up -> loco`；
5. 确认零速度命令行为正确；
6. 再允许 SLAM 发布非零 `/cmd_vel`。

使用结束后，外部流程负责停止、趴下并恢复 `use_sdk=false`。桥的零速度只能停止平面
运动，不会让机器人趴下，也不会释放 SDK 控制权。

package 提供两个现场操作脚本：

- `start_slam_d1_bridge.sh`：确认安全条件、启用 SDK、持续发送 `transform_up`、切换
  `loco` 并在后台启动桥；
- `stop_slam_d1_bridge.sh`：停止桥、发送零速度、持续发送 `transform_down` 并恢复
  `use_sdk=false`。

脚本默认要求人工确认，不能替代现场监护和物理急停。

## 12. 验证策略

### 12.1 无实机验证

- 编译无警告；
- 转换单元测试覆盖支持轴映射、限幅、横移清零、非有限值和安全默认消息；
- 在隔离 Domain 和测试 namespace 中验证 ROS 话题输入输出；
- 验证停止输入后超过超时时间输出归零；
- 不使用 Domain 42，不连接 D1。

### 12.2 网络联调

在自有 NX 上分别确认：

```bash
ros2 topic info /cmd_vel -v
ros2 topic info /slam/pose -v
ros2 topic info /d15041873/command/user_command -v
```

成功条件是自有 NX 能同时发现 SLAM 的两个发布端和 D1 的命令订阅端。D1 与 SLAM NX
不需要互相直接发现。

### 12.3 实机验证

实机验证必须等待机器人上电、现场安全条件具备并获得明确授权。按零速度、极低速度、
短时间运动、超时停止的顺序逐项验收，不直接进行高速或长时间运动测试。

## 13. 已确认事项与待确认事项

### 13.1 已确认

- D1 机器人 namespace 为 `d15041873`；
- D1 使用 ROS 2 Humble、Fast DDS 和 Domain 42；
- 三台 NX 第一阶段统一使用 Domain 42；
- SLAM 与自有 NX 通过 `192.168.123.xx/24` 有线或 USB 网卡连接；
- 自有 NX 与 D1 通过 `192.168.0.xx/24` 公司 Wi-Fi 连接；
- D1 接收 `ddt_msgs/msg/UserCommand`；
- 当前单机双轮足不支持横移；
- SLAM pose 与 D1 body pose command 是不同业务概念；
- 第一期只重点实现运动命令转换与限幅；
- `slam_d1_bridge` 与 `http_ros_gateway` 不同时使用。

### 13.2 后续确认

- SLAM `/cmd_vel` 和 `/slam/pose` 的实际发布频率及 QoS；
- SLAM 是否提供明确的跟踪状态或定位质量接口；
- 大模型如何使用 SLAM pose 进行路径规划和闭环控制；
- 是否需要 pose 超时联锁；
- D1 实机适合的速度上限和最佳发布频率；
