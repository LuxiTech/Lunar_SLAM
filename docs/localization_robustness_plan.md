# 3D 导航定位稳定性优化方案

## 1. 问题与证据

实际导航日志中已经复现两类停止原因：

- ICP 约 2 Hz 发布定位，而跟随器原先在 TF 年龄刚超过 1 秒时就永久停止；记录值为
  1.040 秒和 1.064 秒。
- 单次定位相对路径偏差达到 0.502 米或 0.650 米时，跟随器立即永久停止。

这不是 `map042` 或 `map045` 的地图文件问题。主要故障链是：点云匹配短时延迟或进入局部
极值，可信 TF 暂时中断或发生位姿跳变；跟随器把一次异常直接当作不可恢复故障；ICP 连续
失败后启动 HLoc，但原先缺少重定位位姿与丢失前可信位姿的回接校验。

## 2. 定位数据链

当前链路保持 HLoc、ICP、连续里程计和 IMU 的职责分离：

1. HLoc 提供低频全局粗定位，仍需连续三帧在 0.50 米、20 度内一致。
2. RTAB RGB-D odometry 以约 14 Hz 发布 `/navigation/odom` 和 `odom -> base_link`，负责连续
   局部运动；定位节点只发布唯一的 `map -> odom`。
3. 深度点云 ICP 以约 2 Hz 精配准到选定地图，fitness、RMSE 和相对里程计残差均需通过检查。
   map045 的大面积相似平面会产生有方向性的 ICP 偏差，因此首次 HLoc+ICP 后，后续 ICP 只做
   健康检查，不直接重写 50 cm 验收阶段的连续里程计轨迹。
4. D1 机身 IMU `/d15041873/imu_sensor_broadcaster/imu` 约 400 Hz，用于全局匹配航向初值；
   RGB-D odometry 同时使用 `/sensors/imu/data`，不积分加速度估计位置。
5. `/navigation/active=false` 时在定位输出层冻结最后可信平面位姿；点击出发变为 true 后才累计
   相邻 RGB-D/IMU 里程计增量，停止时再次冻结，避免把静止视觉噪声当作运动。
6. 跟随器消费完整的 `map -> odom -> base_link` TF。

## 3. 位姿门控

### 3.1 连续跟踪门

接受位姿的最大变化由机器人运动包络动态计算：

```text
最大平移 = 0.08 m + 0.20 m/s × min(帧间隔, 2.0 s)
最大航向 = 8 deg + 0.70 rad/s × min(帧间隔, 2.0 s)
```

该设置覆盖当前导航最大速度 0.10 m/s、0.35 rad/s，并保留两倍速度余量和测量噪声余量。
时间戳倒退、非有限数值或超出物理包络的结果均被拒绝。单帧拒绝后保留最后可信位姿，下一帧
正常结果可以直接恢复，避免错误结果在状态中累积。

### 3.2 重定位回接门

ICP 连续失败触发 HLoc 后，新 HLoc+ICP 结果除满足三帧一致和 ICP 质量外，还必须与丢失前
最后可信位姿满足：

- 平移差不超过 0.40 米；
- 航向差不超过 30 度。

超过阈值说明结果可能落入走廊、墙面或重复纹理的错误位置。系统继续保持零速度并重新搜索，
不会因为“错误结果自身连续三帧一致”而接受跑飞位置。首次启动定位没有历史位姿，因此仍允许
正常的全局初始化。

## 4. 跟随器故障恢复状态机

```text
active
  └─ TF 超过 1.5 s 或路径偏差超限
       → localization_degraded（立即连续发布零速度，保留路径和 active 任务）
           ├─ 45 s 内可信定位恢复且仍靠近路径 → active，自动继续
           └─ 45 s 内没有恢复 → localization_lost/path_deviation，永久停止
```

45 秒宽限期由本机 `map045` 完整 HLoc 模型加载及定位实测确定；两次冷启动分别约需 23～32
秒。宽限期内车辆始终为零速度，因此延长等待不会扩大运动风险。急停、人工停止、手动速度接管
和导航速度发布超时仍走原有立即停车链路，不受恢复状态机影响。

网页在降级期间显示“定位恢复中（已停车）”，并说明恢复后会自动继续。

## 5. 本地验收结果

- `map045` HLoc→ICP 冷启动成功，fitness 约 0.86～0.89。
- ICP 节点成功订阅 D1 机身 IMU。
- 原实现静止约 4 分钟仍反复接受 5～14 cm 假位移，并出现 18～39 cm ICP 候选跳变，证明
  “每帧直接做 scan-to-global-map ICP”会在相似平面中游走。
- RTAB RGB-D odometry 独立静止 30 秒取得 336 帧，X/Y 跨度 1.08/0.76 mm，航向跨度 0.061°。
- 完整 HLoc + ICP + RGB-D odometry + TF 链静止 45 秒取得 689 帧；X、Y、航向跨度和终点
  位移均为 0。真实 `/cmd_vel` 六个分量全程为 0，导航未激活。
- 修复 RTAB odometry 被 `/opt/MVS/lib/aarch64/libusb-1.0.so.0` 抢先加载导致
  `libusb_set_option` 符号缺失的问题；导航启动时优先使用系统 libusb。
- 修复 AArch64 优化构建下 Eigen 通用 4×4 求逆表达式递归导致的 SIGSEGV，改为平面刚体
  解析逆变换，并完成真实整链重启验证。
- 故障注入：暂停 ICP 4 秒后，隔离跟随器进入 `localization_degraded`，输出严格为零；恢复
  ICP 后状态自动回到 `active`，无需再次发送 start。
- 故障注入全程使用 `/test_navigation/cmd_vel`，未连接机器人；真实 `/cmd_vel` 三个分量始终
  为零，真实导航未激活。
- 当前全工作区累计 226 项测试通过，0 失败（6 项跳过）。

## 6. 实车分阶段验证

1. 原地定位 2 分钟：记录 fitness、RMSE、位姿跨度和拒绝原因，确认没有连续失败。
2. 原地慢速转向：保持不超过 0.10 rad/s，确认 IMU 初值能降低航向修正量。
3. 直线低速导航：速度先限制为 0.05 m/s，路线控制在 1 米内，操作员持有急停。
4. 人为遮挡相机 2～4 秒：预期立即零速、网页显示恢复中，解除遮挡后自动继续。
5. 遮挡超过 45 秒：预期进入永久停止，必须重新确认定位和路径后人工出发。
6. 收集至少三次完整 rosbag 后，按真实正常/异常分布再评估是否收紧 ICP 的 0.25 fitness
   和 0.15 米 RMSE 阈值。没有数据分布前不应盲目提高阈值。

如果厂家后续提供可靠的机身里程计，应把里程计增量作为 ICP 平移和航向初值，并由 IMU约束
角速度；当前 D1 话题中没有可用的轮式里程计，因此本阶段不对 IMU 加速度进行位置积分。
